## 共用文件与脚本约定

以下为后续实施应建立的约定，并非本次保存计划时已生成的文件。

| 位置 | 用途 |
| --- | --- |
| `scripts/test-data.mjs` | Node ESM 脚本，复用 `apps/web` 中已安装的 Faker |
| `.local/test-data/<batch>/accounts.json` | 本地凭据、用途、注册状态和真实账号 ID；脚本续跑依据 |
| `.local/test-data/<batch>/accounts.md` | 供用户使用的账号文档，与 JSON 同步 |
| `.local/test-data/<batch>/manifest.json` | 批次、seed、目标 API、素材信息、发布映射及验证状态；不存 token |
| `.local/test-data/<batch>/videos/`、`covers/` | 原始 MP4 与对应封面 |
| `.local/test-data/<batch>/evidence/` | 本地日志、截图、请求摘要、媒体检查结果；凭据及 token 脱敏 |
| `.local/test-data/<batch>/report.md` | 本批次联调结果、步骤、缺陷和后续使用入口 |
| `docs/integration-test-verification.md` | 后续交付时生成的可入库汇总，无密码、token 或远程连接密钥 |

仓库根 `.gitignore` 增加 `/.local/test-data/`，保留其他内容。该路径下的测试账号文档允许记录本次专用账号的明文密码，这是用户明确要求的交付；真实环境密钥、JWT、refresh token 不写入这些文档。

从仓库根执行脚本；默认 seed 为 `20261024`，默认 batch 为北京时间生成的 `YYYYMMDD-HHmmss`，显式指定 batch 时恢复该目录。每阶段应先记录实际 batch，后续命令替换示例值并保持一致。

```powershell
node scripts/test-data.mjs generate --batch 20261024-120000 --seed 20261024 --only metadata
node scripts/test-data.mjs generate --batch 20261024-120000 --only media
node scripts/test-data.mjs register --batch 20261024-120000 --api-base http://localhost:8095
```

`generate` 默认 `--only all`；metadata 只生成账号候选及媒体元数据，不调用后端；media 使用已有元数据生成并验证媒体。`register` 仅处理明确待注册账号，不自动发布作品。脚本应拒绝用不同 seed 覆盖同一批次，遇到损坏或不一致的清单明确报错，不静默重建凭据。

## 共用验收及记录方式

- 每条结果使用“待执行、通过、失败、受阻”之一，记录北京时间、账号别名、素材编号、步骤、预期、实际、证据路径、缺陷及复测结论。
- 请求摘要记录方法、路径、HTTP 状态、耗时和必要的脱敏响应；不记录 Authorization、密码请求体或 refresh token。截图避开存储面板中的凭据。
- 注册每 IP 5 次/小时，登录 10 次/分钟，以执行时源码和真实响应复核。已有次数会减少本批次可用额度；不清除计数或绕过限流。发生 429 后，记录窗口并等待正常恢复，分段等待、持续提供有意义进度。
- 写请求超时或响应丢失后先读回判断实际结果；确认不存在才重试。账号和作品不因续跑而重复创建。
- MQ 相关结果最长等待 30 秒，低频读回，记录首次可见延迟；超时记失败或受阻，不能伪造本地成功数据。
- 所有阶段的实施记录使用下面模板，完成时追加真实结果，不提前勾选。

```markdown
### 实施记录
- 执行时间 / batch：待执行
- 完成步骤 / 实际产物：待执行
- 检查命令与结果 / 证据：待执行
- 缺陷与修复 / 版本变化：待执行
- 受阻项 / 下一阶段交接：待执行
```
