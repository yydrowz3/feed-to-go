# 子计划 06：双账号互动与私信

前置：[05 真实发布作品](integration-test-05-upload-publish.md)。下一阶段：[回归与交付](integration-test-07-regression-handover.md)。当前状态：通过。05 的音频听感已由用户逐一试听确认通过。

## 目标与测试对象

使用 A、B 及本批次作品验证点赞/取消、关注/取消、评论及删除本人评论、双向私信及对端读取。优先操作 01（A）和 05（B），其余账号和作品保留手工使用。

所有操作通过真实浏览器完成，必要时以 API 读回补充。若工具支持隔离浏览器上下文，可为 A、B 分别使用；同 origin 普通标签通常共享 localStorage，不能将两个普通标签当成隔离账号。无隔离能力时顺序退出并登录切换，严格核对当前身份。

## 实施步骤

### 1. 验证点赞与取消点赞

- B 打开 A 的作品 01，先记录本人是否点赞及当前计数，再点赞一次；等待真实读取显示已点赞及计数变化。
- 查看 B 的喜欢列表和视频详情，刷新后状态仍一致；A 重新进入详情确认真实计数。
- B 取消点赞，确认状态、喜欢列表及计数恢复到操作前基线；不假设全局计数一定从 0 开始。
- A 对 B 的作品 05 重复点赞和取消，验证换号后的读写与缓存隔离。
- MQ 读回最多等待 30 秒，低频检查并记录提交到首次可见时间；若接口成功而数据库读取一直未变，检查消费者并记录失败，不用前端乐观状态代替读回。

### 2. 验证关注与取消关注

- A 打开 B 的用户主页，记录关注状态和双方计数，关注 B；检查 A 的关注列表和 B 的粉丝列表。
- A 打开关注视频流，确认 B 已发布的本批次作品可按真实接口结果显示；记录缓存或 MQ 延迟。
- A 取消关注，验证双方列表和计数回到基线；B 对 A 完成相同操作。
- 完成本组可恢复操作后，按最终演示状态再建立 A、B 互相关注并读回确认，保留供后续手工测试。

### 3. 验证评论及删除本人评论

- 使用英文 dummy 句子并加批次/用例标记生成评论内容，记录作者、video_id、真实 comment_id 及时间，不写个人信息。
- B 在作品 01 评论，等待列表真实可见；换 A 查看确认作者正确，A 不应拥有删除 B 评论的本人删除入口。
- B 重新登录删除该本人评论，等待真实列表确认消失；A 在作品 05 重复本人评论及删除流程。
- 最终各增加一条英文演示评论，读回后保留，使作品在交付时有可见互动数据；删除验证使用的评论和最终保留评论分别记录。
- 留意评论限流，异步新增或删除超时按真实结果记录，不通过刷新本地列表强行伪造成功。

### 4. 验证双向私信并交接

- A 从 B 的主页进入会话，发送带 batch 和用例编号的英文测试消息；记录发送成功后的真实 message_id 和会话对象。
- B 登录后重新进入与 A 的会话，确认能读取该消息，再回复；A 重新进入确认读到回复。
- 检查联系人列表不会重复创建同一对象，切换会话及账号后消息不会串入错误会话。
- 刷新页面再次读取本次消息，验证服务端持久化。当前前端没有实时接收和历史分页，不以实时推送或超过 50 条历史作为本次验收要求。
- 发送结果未知时先重新读取会话比对 message_id、内容及时间，不自动重发。最终保留双方关注、各一条演示评论及双向消息；点赞保持完成取消后的基线。
- 汇总每条动作的成功响应、实际读回、延迟、最终状态及缺陷。阻塞问题修复后重走对应步骤，再交接 07。

## 验收条件

- [x] A/B 双向点赞和取消均有真实读回，喜欢列表与详情一致。
- [x] 双向关注和取消验证完成，最终互相关注状态可读取。
- [x] 双方本人评论可发布和删除，最终保留评论可被对方读取。
- [x] 双向消息在对方重新进入、刷新后可读，会话与账号隔离正确。
- [x] 异步延迟、最终保留数据、缺陷及未通过项已记录。
