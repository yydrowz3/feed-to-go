### 2. 生成并控制文件大小

- 使用目标区间中点估算总码率，扣除音频码率和容器开销，采用带合理缓冲区的恒定码率编码，保证运动及编号清楚。
- 逐个生成到批次临时文件，FFmpeg 成功退出、参数和大小检查合格后再替换对应目标文件；每完成一项立即更新清单。
- 未落入大小区间时，根据实测结果修正码率并重新编码，最多调整 3 次，仍失败则记录错误并停止该项，不补零或截断 MP4。
- 03～08 必须大于 5 MiB，且文件大小不为 5 MiB 的整数倍；根据实测确认末片非空并小于 5 MiB。
- 已验证且 MD5 未变化的素材在同 batch 重跑时跳过；缺失或损坏素材只重建对应项。已有发布映射的文件禁止静默重建，明确提示需新批次。

### 3. 提取封面

- 从每个视频第 1 秒抽取一帧，保留编号；最长边缩放至 960 像素，保持比例，输出对应格式。
- 01～04 使用 `.jpg`，05～06 使用 `.png`，07～08 使用 `.webp`；同编号视频与封面在清单中一一对应。
- 每张必须可解码、非空且小于 10 MiB；超限时调整尺寸或压缩质量并重新导出，不修改视频文件以适配封面。
- 逐张视觉查看，核对编号、横竖比例、清晰度及对应关系，保存必要的预览证据。

### 4. 验证视频及分片信息

- 使用 FFprobe JSON 检查容器、编码、像素格式、宽高、帧率、音轨与时长；时长误差控制在 0.2 秒以内。
- 对全部 MP4 执行 FFmpeg 完整解码到 null，要求退出成功且无解码错误。分别查看前、中、后代表帧，确认时间变化和运动画面。
- 从磁盘流式计算视频和封面 MD5，记录实际字节数；按 `chunkSize = 5 * 1024 * 1024` 计算 `totalChunks = ceil(size / chunkSize)` 和末片字节数。
- 清单保留目标值与实测值，保存 FFprobe、完整解码和文件校验结果到 evidence；每组验证通过后才标为可上传。
- 可用本机浏览器先打开代表性横屏、竖屏、方形及无音轨文件检查播放；真实后端媒体播放仍留给 05 验证。

### 5. 交接素材使用清单

- 生成便于手工上传的素材列表，包含编号、英文标题描述、视频路径、封面路径、用途及作者别名。
- 核对 8 个 MP4、4 张 JPEG、2 张 PNG、2 张 WebP 均存在；后续命令和报告使用实际 batch。
- 将本地验证结果追加到批次报告，列出实际总大小及失败项；只有全部 8 组通过，才交接真实上传。
