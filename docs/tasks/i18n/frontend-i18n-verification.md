# 前端 i18n 实施与验收

日期：2026-10-24。实施方案：[frontend-i18n-plan.md](frontend-i18n-plan.md)。前端版本由 **0.1.12 → 0.1.13**，作为一个完整实施单元升版一次。实施起点工作区干净；在现有代码上整合，未进行数据库结构迁移。

## 交付内容

- 引入精确版本 `i18next 26.5.10` / `react-i18next 17.1.7`，同步锁文件。pnpm 生成的 release-age 排除项仅限这两个精确版本。
- `en`、`zh-CN`、`ja` 三语随包加载，11 个命名空间。默认英文，恢复独立 Storage 偏好；初始化先于 React 渲染，正常应用及配置错误页均处于 Provider 内。
- 顶部原生语言选择器、桌面和移动导航、完整界面与无障碍文案、Zod 校验、业务错误、动态 Toast、上传阶段、日期及数字格式化。
- 切换语言仅更新 i18n 状态，不重新创建路由、查询缓存、表单或上传任务。默认用户名和标题仅在展示层补全，用户内容保持原文。
- 共享错误清单、Go / TypeScript 生成结果、生成检查脚本及三语映射。覆盖当前前端调用的接口、共用鉴权与限流，保持成功响应结构及上传附加字段。
- 按类型区分用户名冲突、凭据、权限、资源缺失、上传缺片、大小限制、Redis 故障及内部异常。发布说明需同时包含 HTTP 状态变化，见 [错误码契约](api-error-codes.md)。

## 复现

常规检查从 `apps/web` / `apps/api` 执行表中命令。浏览器正常构建需设置有效的 `VITE_API_BASE`；额外配置错误构建可在仓库根的独立 PowerShell 进程执行：

```powershell
$env:VITE_API_BASE = ''
pnpm --dir apps/web exec vite build --outDir ../../.local/i18n/config-dist
```

从 `apps/web` 启动隔离回归服务器：

```powershell
pnpm test:browser --media <本机测试MP4的路径> --config-dist ../../.local/i18n/config-dist
```

打开 `http://127.0.0.1:5186/__checks`，点击 **Run checks**，通过时标题显示 `Browser regression: passed`；JSON 报告也可从 `/__report` 读取。`--config-dist` 可选，不传时跳过专用配置错误构建检查。测试凭据和交互均限于 fixture。

部署顺序：先后端错误契约，再前端。旧后端缺失/未知 `code` 或返回非 JSON 时，前端使用 HTTP 状态和操作上下文的通用提示；原始响应保留在 `ApiError.payload` 中用于诊断。
