# 子计划 04：真实注册与登录会话

前置：[03 环境就绪](integration-test-03-environment.md)。下一阶段：[上传、发布与播放](integration-test-05-upload-publish.md)。当前状态：通过；浏览器自动刷新已由 05 的真实失效会话补验，原执行时待验记录保留在下文。

## 目标和接口

将候选资料变成 5 个真实可登录账号，首个通过浏览器注册，其余通过后端接口注册，并验证真实会话流程。使用现有 `/account/register`、`/account/login`、`/account/findByUsername`、`/account/refresh`、`/account/logout` 和 `/account/getProfile`。

本阶段不扩展改名、修改密码、头像或简介测试，也不改变已生成账号的凭据，方便后续复用。

## 实施步骤

### 1. 实现注册命令的续跑和限流处理

- 补齐 `register --batch <实际批次> --api-base <实际API>`；先读取清单校验环境，预查候选用户名，避免把已有账号覆盖或认领为本批次创建。
- 对 registered 跳过注册；对 unknown 先查询并尝试用已保存密码验证，确认归属后回填 ID；对冲突且密码不符的候选只调整该未注册项的字母后缀并同步文档。
- 注册返回成功后通过真实查找/登录响应取得 account_id；登录返回的用户名与 ID 必须匹配，禁止虚填序号作为 ID。
- 请求结果未知时立即持久化 unknown，不自动重发注册；failed 记录脱敏错误，续跑前再次查证账号是否存在。
- 遵守注册 5 次/小时、登录 10 次/分钟，节制请求并持久化已完成状态。429 后等待真实窗口恢复，不清除 Redis 限流键，不换 IP 绕过。
- 注册接口本身不返回 ID；脚本只保存账号 ID、状态和脱敏结果，JWT/refresh token 只在内存中用于本次检查。

### 2. 首个账号通过浏览器真实注册

- 使用本批次 A 的用户名和密码打开 `/account/register`，核对页面字段，提交一次。
- 验证注册成功提示和返回登录页；随后登录，读取真实 ID，更新 accounts.json、accounts.md 和注册证据。
- 结果未知时通过用户名查找和登录确认，不因未见提示重复提交。保存的截图不展示密码。
- 在继续自动注册前确认 A 已持久化为 registered，脚本不会再次消耗其注册额度。

### 3. 创建并验证其余 4 个账号

- 使用注册命令依次处理 B、C、D、E；每个成功后立即保存状态，再处理下一项。
- 对全部 5 个账号分别验证真实登录响应，再以各自 token 调用受保护接口确认鉴权成功；不得仅用公开资料接口证明 token 有效。
- 注册限流窗口若已有其他请求，保存进度并等待恢复；不为了凑齐数量改用 SQL 插入绕过真实注册链路。
- 检查脚本响应和日志不输出 token、密码；本地账号文档完整可复制，所有已注册 ID 来自真实后端。

### 4. 验证浏览器登录与会话

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 登录返回目标 | 匿名进入 `/video`，登录 A | 回到发布页，身份为 A |
| 刷新恢复 | 登录后刷新页面并读取本人资料 | 登录状态恢复，账号 ID 一致 |
| 错误密码 | 正常退出后对 A 输入错误密码一次 | 明确失败反馈，不建立会话，不显示成功 |
| 退出 | A 登录后退出，再访问受保护页面 | 本地会话清除，受保护页面返回登录 |
| 换号 | A 退出后登录 B，再查看资料、作品、喜欢及消息入口 | 无 A 的缓存、草稿或身份残留 |
| C～E 可用 | 分别使用已保存密码登录验证 | 账号名、ID 和凭据对应 |

- 登录次数超过当前一分钟窗口时等待恢复，不快速轮询登录接口。
- 原生 access token 过期通常不适合等待验收；如验证自动刷新，在本机测试会话内通过支持的浏览器控制将 access token 替换为无效值，保留该测试账号有效 refresh token，再发受保护读取请求。确认最多一次刷新和重放，验证后恢复正常登录；不改服务器时间或全局 JWT 配置。
- 仅在工具支持该会话操作时执行上一项；无法执行则明确记录自动刷新待验，不能用直接调用 refresh 接口冒充浏览器自动刷新通过。

### 5. 修复问题并交接

- 失败时保留输入条件、HTTP 状态、脱敏响应和页面表现，区分 CORS、限流、依赖、接口及前端会话问题。
- 先修复阻塞缺陷并运行对应测试，再用同一账号重走失败路径；注册冲突或错误密码的现有 HTTP 状态如有问题，应保留复现并在既有契约下修复。
- 交接 A、B 的真实 ID 和使用入口；文档中的密码仅留在被忽略目录。报告明确列出 5 个账号的真实可用状态和未完成场景。
