## 目标与边界

完善 `/account`，完成注册、改密码、设置、`/u/$id`、`/messages` 和 `/messages/$peerId`。沿用阶段 01 的登录和退出，复用阶段 02 的关注动作、视频卡片和缓存同步，不重写会话、请求层或播放器。

## 数据接口与缓存

所有接口继续由阶段 01 的客户端封装。注册、登录、改密码为 `auth: 'none'`；其余按下表处理。

| 功能 | POST 路径与参数 | 结果/约束 |
| --- | --- | --- |
| 注册 | `/account/register { username, password }` | message；成功后登录，不自动登入 |
| 改密码 | `/account/changePassword { username, old_password, new_password }` | message；无需已登录 |
| 改名 | `/account/rename { new_username }` | 新 token；required，保留已有 refresh token |
| 退出 | `/account/logout {}` | required；无论响应如何都结束本地会话 |
| 用户资料 | `/account/findByID { id }` | id、username、avatar_url、bio；公开 |
| 用户作品 | `/video/listByAUthorID { author_id }` | Video[]；公开，注意 URL 大小写 |
| 本人喜欢 | `/like/listMyLikedVideos {}` | Video[]；required，不是 FeedVideoItem[] |
| 粉丝 | `/social/getAllFollowers { following_id }` | followers、follower_count；required |
| 关注 | `/social/getAllVloggers { follower_id }` | followings、followings_count；required，响应不是 vloggers |
| 消息历史 | `/message/list { peer_id }` | messages；required，当前后端只返回最近 50 条 |
| 发消息 | `/message/send { to_id, content }` | 新 Message；required |

在统一 key 工厂中扩展：

- `['account', sessionId, viewerId, accountId]`：资料。
- `['works', sessionId, viewerId, authorId]`：作品。
- `['my-liked', sessionId, viewerId]`：本人的喜欢列表。
- `['messages', sessionId, viewerId, peerId]`：单个会话。
- 粉丝和关注复用上一阶段的 followers / followings key，不能另外建立独立的“我的关注”数据副本。

## 实施步骤

### 1. 完善账号入口与注册

- 未登录时显示已有 LoginForm 和注册、修改密码导航；登录成功遵守已有 redirect 行为，不另建 login 路由或表单状态 Store。
- 已登录时替换阶段 01 账号占位，显示真实资料、身份、设置入口、粉丝数、关注数、“作品”和“喜欢”标签。
- 资料查询失败可继续展示 token 中的身份，但给出失败/重试提示；不要把 token 身份伪装成成功加载的完整资料。
- 注册表单沿用旧用户名/密码 trim 和非空校验，用 TanStack Form 和现有 Zod；不增设密码复杂度、确认密码或邮箱字段。
- 注册成功通知并返回 `/account`。从登录入口带来的合法 redirect 可透传注册流程，使用户随后登录仍能回原页；不得接受外部跳转地址。
- 提交按钮和回车共用一个 onSubmit，提交中禁用重复操作；成功后清理密码，失败保留可编辑内容。

### 2. 修改密码

- 页面始终公开；表单包含用户名、旧密码、新密码。当前已登录时可预填用户名，仍允许用户编辑，符合旧接口。
- 按旧版 trim / 非空规则提交，不把密码保存到全局状态或日志。
- 成功后，如果提交用户名等于当前会话用户名，调用共享会话结束流程，取消旧任务并清缓存，避免 token 仍显示已登录。
- 未登录或修改的是其他账号时，不清理无关会话；均提示密码已修改并导航至 `/account`。
- 失败时保留当前会话与表单并展示一次错误。请求返回前用户已经换号时，不退出新的无关账号。

### 3. 设置、改名与退出

- 将阶段 01 最小设置页扩为旧版账号设置布局，包含身份、改名、改密码入口和退出。
- 改名表单打开时填入当前用户名；取消关闭表单，提交 trim 后非空的新名。响应成功后仅替换 access token，保留 refresh token，不将整个会话当成重新登录。
- 更新 Store 的 username / claims，并更新或失效资料、作品作者显示、社交列表和消息联系人相关缓存；已有视频标题等无关字段不重置。
- 改名响应与刷新响应都核对所属会话，较早凭据响应不得覆盖较新凭据。遇到同会话 access token 已变更时，应由基础层的凭据提交检查决定接受或丢弃，不能在页面直接 setState 绕过。
- 退出继续使用共享确认弹窗和阶段 01 退出方法。退出过程中禁用重复点击；接口失败仍清理两个 token、Query 缓存及会话任务并回首页。
- 设置说明改写为用户可理解的行为，移除直接展示 token、接口路径等实现细节。

### 4. 本人作品和喜欢列表

- 作品和喜欢使用独立 Query，只在相应账号/标签需要时启用；默认作品，首次打开喜欢才请求喜欢列表。
- 视频卡片复用阶段 02 的展示组件，支持封面、标题、计数、日期和详情导航。Video 日期按字符串解析，不按 Feed 秒级时间处理。
- 每个列表独立展示首次加载、失败重试、空态。服务端 null 归一化为 []，失败不能显示成“暂无作品”。
- 阶段 02 点赞成功时，除了现有 Feed 和详情，还要失效 my-liked；取消喜欢后从已经缓存的喜欢列表移除目标。新点赞仅在有完整 Video 数据时插入，不用 FeedVideoItem 冒充 Video。
- 退出或切换账号时立即关闭列表抽屉并重置本地标签；旧请求不能覆盖新账号的作品或喜欢。
- 第四阶段发布成功后失效 works 和当前用户资料；这一阶段为后续保留同一 key，不先实现发布逻辑。

### 5. 粉丝/关注抽屉与用户主页

- 将本人账号页与用户主页的列表抽屉抽为共享 FollowListDialog。列表和计数均消费 Query，不复制到页面 reactive 风格对象或 Zustand。
- 本人账号页获取本人 followers / followings，计数优先使用后端 count 字段；不是用用户名或错误字段判断关系。
- 用户主页校验 id 后并行加载资料与作品；资料失败展示用户加载错误，作品失败保留已成功资料并单独重试。
- 匿名可看资料和作品；粉丝/关注列表因接口要求鉴权，显示登录引导，不展示伪造的 0 计数。登录后再启用相应 Query。
- 他人主页的关注/取消关注复用阶段 02 的动作；本人主页不显示关注自己。按钮状态以本人的 followings 判断，不能拿目标用户的 followings 判断。
- 查看他人的粉丝/关注必须传目标 ID。点击列表用户关闭抽屉并导航 `/u/{id}`；切 id 清理旧弹窗及局部错误。
- “私信”按钮对他人有效：匿名进入带 redirect 的登录，已登录导航 `/messages/{id}`；禁止本人向自己发信。
- 头像与简介仅展示后端现有字段，图片失败使用共享头像后备，不增加编辑入口。

### 6. 联系人入口

- `/messages` 继续以本人的关注列表和粉丝列表组成联系人，不虚构后端未提供的会话目录。
- 按账号 ID 去重，保留“先关注列表、后补粉丝列表”的顺序，排除本人。两组列表并行请求。
- 一组失败时可显示另一组已成功的联系人，并明确提示失败部分可重试；两组都成功且为空才显示无联系人。
- 点击联系人导航到 `/messages/{peerId}`。直接打开不在联系人中的有效用户会话仍可使用，不额外限制互关。
- 在移动端保留返回联系人列表的入口；导航和焦点使用共享外壳，不再嵌套第二套页面布局。

### 7. 私信历史与发送

- 会话页先校验 peerId 是正安全整数且不等于本人 ID，再并行请求目标资料和消息；不合法时不调用 API。
- messages=[] 是真实空会话；加载失败展示错误和重试。后端最近 50 条按 created_at 升序展示，时间相同按 id 升序，不能声称已获取全部历史。
- 使用 TanStack Form 管理内容，trim 后非空才可发送；每个会话只允许一个发送请求在途，按钮提交与键盘提交复用同一入口。
- 成功返回的真实 Message 按 id 去重插入对应会话 Query；只有仍停留在原会话且同一 session 时，才清空当前草稿并滚到新消息。
- 失败保留草稿并提示，禁止自动重试发送，避免响应丢失时重复发信。
- 首次加载、切会话和本人发送成功滚到底部；普通重渲染不反复强制滚动。
- 切换 peerId 时立即重置输入及局部错误，取消旧读取。发送请求捕获原 peerId / sessionId，不允许迟到结果写到新会话或清掉新草稿。
- 离开或退出时释放滚动及请求资源；主动取消不显示“发送失败”。如果请求已被后端接收，取消不会撤销消息，不能在 UI 宣称已撤回。
- 不新增定时刷新、WebSocket、SSE、未读数或消息已读写接口；用户重新进入/手动重试时才重新读取。
