# 子计划 05：上传、续传、发布与播放

前置：[02 素材验证](integration-test-02-media-fixtures.md)、[04 真实账号](integration-test-04-auth.md)。下一阶段：[双账号互动与私信](integration-test-06-social-messages.md)。当前状态：通过，测试音实际听感已由用户逐一试听确认通过；具体证据见[汇总](integration-test-verification.md)。

## 目标和接口

通过真实浏览器发布 8 个素材，A 发布 01～04，B 发布 05～08，各 4 个。验证选择预览、MD5、5 MiB 串行分片、封面上传、取消及刷新续传、作品刷新和后端媒体播放。

沿用现有 `/video/chunk/init`、`/video/chunk/upload`、`/video/chunk/status`、`/video/chunk/complete`、`/video/uploadCover`、`/video/publish`，不改用整文件上传替代分片验收。

## 实施步骤

### 1. 检查素材、作者和发布状态

- 重新校验 8 组本地文件与清单 MD5 一致，读取真实作者 ID，核对各自标题、描述和对应封面。
- 核对后端 Redis、worker 和上传目录就绪，浏览器当前账号与目标作者一致。
- 同批次已有 video_id 的素材先读取详情与作者作品列表确认，不再次发布。上次结果未知的素材先按作者、标题、描述、时间及媒体地址读回查证，确认未发布才恢复操作。
- 清单为每项记录 publish_status（pending、published、unknown）、作者 ID、video_id、play_url、cover_url、发布时间和证据；中间已上传的媒体地址保存为恢复证据。

### 2. 发布小文件和基础多片素材

- A 在 `/video` 发布 01、02，填写清单英文标题和描述，选对应本地文件；检查视频预览和封面，确认竖屏展示正常。
- A 发布 03，检查至少两个分片按索引串行上传，末片长度正确；封面请求使用真实 FormData 且不手写 boundary。
- 检查浏览器实际 hash-wasm 运行；使用本地 MD5 与 init 的完整文件哈希、各片哈希对照，进度以已确认字节为准。
- 每次成功立即保存真实 Video 返回和详情链接，核对本人作品刷新可见，禁止仅凭成功 toast 计为发布通过。

### 3. 验证取消与刷新续传

| 素材 | 操作 | 必须保留的证据 |
| --- | --- | --- |
| 04 / A | 上传至少一片并确认后，点击取消，再用同一文件重试 | 原 upload_id、已确认索引；恢复跳过已有片，只合并和发布一次 |
| 05 / B | 上传至少一片并确认后，在合并前刷新，重新选择同一文件及封面并填写元数据 | 相同完整 MD5、恢复的 upload_id/索引、末片大小、最终 video_id |

- 若本机上传太快，通过本机浏览器网络限速或受控暂停创造操作窗口；不把取消发生于合并之后误记为分片续传通过。
- 取消后不进入封面或发布步骤；主动取消展示可恢复提示。刷新后由用户重新选择 File，不能声称浏览器自动恢复了文件。
- init/status 的实际 uploaded_chunks 与后续请求索引应能证明跳过已有分片；不能只根据进度条推断续传成功。
- 恢复后同样完成封面与真实发布；complete 或 publish 结果未知时先读回，不自动反复提交。

### 4. 发布剩余素材并验证媒体

- B 发布 06、07、08，检查无音轨视频、更多分片和较大文件的进度；各素材保持对应作者及封面。
- 所有 8 个作品逐一打开详情，确认画面编号、英文标题描述、封面、播放时间推进、结束与拖动进度；带音轨素材实际检查测试音，无音轨素材无播放错误。
- 核对 API、play_url 和 cover_url 的请求直达后端。对媒体发起实际 Range GET，确认 206、Content-Range 和请求范围一致；同时检查浏览器拖动播放。
- 使用后端返回的视频 URL 读取内容并计算 MD5，与本地源文件比较；网络下载只用于本次测试生成并上传的自有素材完整性验证，校验临时副本可置于 evidence。
- 核对 A、B 的作品列表各包含本批次 4 项；公开详情、公开用户作品和首页能读取相应真实内容，允许记录异步出现延迟。

### 5. 检查错误恢复与保存结果

- 验证空标题或缺少文件被本地拦截，失败不应发发布请求；不为边界校验生成超 200 MiB 的交付视频。
- 在本机受控网络条件下对一条分片制造一次传输失败，验证有限重试、已确认进度不重复计数；恢复后沿用同素材完成，避免创建第 9 个作品。
- 封面或发布阶段若出现真实失败，验证已有媒体检查点复用和结果未知提示，先查作品再决定是否重试。未实际触发的失败路径标待验，不宣称全部故障注入通过。
- 阻塞缺陷立即修复、局部测试并复测；保存各项文件大小、片数、上传/合并/发布耗时和真实 ID。
