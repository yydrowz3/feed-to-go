# 前端实施约定

本文件适用于 `apps/web` 内的全部改动。迁移任务还需遵守 [迁移索引](../../docs/react-migration-00-index.md) 与对应阶段计划；提交信息遵守 [提交规范](../../docs/commit-conventions.md)。

## 项目元数据

- `package.json` 是前端名称、作者、仓库地址、工具版本与应用版本的唯一来源，修改时保留已有 scripts、依赖和用户改动。
- 当前项目为私有应用；仓库尚未声明开源许可证，使用 `private: true` 和 `license: UNLICENSED`，不得自行改成某个开源许可证。
- 不将前端应用版本与后端版本、依赖版本或迁移阶段编号绑定。

## 每次前端实施更新版本

- 每次完成有前端实际改动的实施单元，必须更新 `apps/web/package.json` 的 `version`。普通任务以一次完整交付为一个单元；迁移子计划以一个编号实施步骤为一个单元，不能整阶段只更新一次。
- 范围包括业务代码、样式、资源、前端配置、脚本、依赖声明或测试的实际改动。纯文档/规则修改、只运行验证且无前端改动、仅修改后端，不触发前端升版。
- 默认递增 patch，例如 `0.1.0` → `0.1.1`；明确发布新功能版本时递增 minor，破坏性版本变更递增 major。不得降版，也不因反复调试、测试或构建而在同一实施单元中重复升版。
- 完成本单元实现和相关检查后、创建提交或交付前，从 `apps/web` 执行：

  ```powershell
  pnpm version:bump
  ```

- 如本单元明确需要 minor / major，则使用 `pnpm version minor --no-git-tag-version --no-git-checks` 或 `pnpm version major --no-git-tag-version --no-git-checks`，不再执行默认 patch 命令。`--no-git-checks` 仅允许在尚未提交的实现旁更新版本，不暂存、提交或清理其他工作区改动；实现检查及提交检查仍必须执行。
- 本单元已经更新过版本时，先核对工作区/该单元提交，避免重复递增；后续独立实施单元仍需再次更新。版本相关文件必须与对应实现一起交付；按迁移计划提交时放在同一步 commit，不另建只升版的提交。
- 版本命令不得自动创建 Git commit、tag、push 或发布包。不得将升版命令挂在 `dev`、`test`、`build`、`lint` 等常规命令的生命周期上。
- 升版后检查 `package.json` 的完整性、版本前后值、变更范围及相关检查结果，在实施记录和交付反馈中写明版本变化。仅应用版本/元数据改变时不重新解析或升级依赖；若工具修改锁文件，检查并仅保留必要同步。
- 历史已交付步骤不追溯改版本或改写提交；本规则从引入时开始执行，初始应用版本为 `0.1.0`。
